## Read this first: verify the premise before building, including your own

Three issues today had a false stated premise. **Two of them I wrote the same day.**

- **#696** — claimed the route was orphaned and Skip had no button. Both fixed weeks
  earlier. What survived was different and worse (below).
- **#901** — I claimed allergens were "collected nowhere" and clash-flagging was
  never built. Both false: `app/profile/preferences.tsx` collects them,
  `useDietaryConflicts` (#41) flags them. Cause: one true narrow observation
  ("onboarding collects cuisines only") generalised one step too far.
- **#897** — I claimed `otto-widget@0.5.4` was unpublished from npm. It was *never*
  on npm; it resolves from **GitHub Packages**, and `.npmrc` asserts the opposite.

The failure mode isn't carelessness in any one case — it's over-generalising a true
observation at write-up time. Re-verify before building, even hours later.

Corollary that paid off twice in one issue: **check whether the server already sends
what the client is "missing".** `weekly_menu.go` and `daily_menu.go` both ship
`DietaryTags`/`Allergens` — with a comment stating the intent — while the client TS
interfaces omitted the fields, silently discarding them. Read the Go model before
scoping any API work.

## The big one: running it found what reviews didn't

Every significant bug today came from *driving the app*, not reading it. All of it
passed CI, tests and review the whole time.

- **#904 (P0)** — every tiffin subscribe returned HTTP 500. `normaliseDayVariants`
  returned `""` into a **jsonb** column. Proven by A/B against production: without
  `dayVariants` → 500, with it → 201. It was undiagnosable because the DB error was
  discarded — production logs held only `status: 500`, no SQLSTATE. **That logging
  gap was the real cost.**
- **#696/#898** — Skip had *never worked once*. Client sent RFC3339 (`time.Time`
  JSON) to a Go handler parsing `"2006-01-02"`. Hidden behind an error fallback
  reading *"It may already be past the cutoff"* — a format failure rendering as a
  plausible business rule.
- **#909** — the notification socket gave up permanently; #892's backoff sweep had
  missed it. Spotted in a Metro log while `order-ws` reconnected beside it.

**Hedging copy ("may", "might") is a smell worth chasing.** Twice today it was
camouflage over a total failure.

## Environment — hard-won

- **Deploys can fail completely silently.** Two independent blockers today, both
  invisible from GitHub (green CI, merged PRs, auto-closed issues) while a P0 sat
  undeployed for hours. Only `kubectl get stages -n kargo-homechef` and
  `argocd app get homechef-api` showed it. **Check those before believing a deploy.**
  - Dead KEDA prometheus trigger → ScaledObject Degraded → 5 ArgoCD apps Degraded →
    Kargo health gate fails. Fixed in `tesserix-k8s#147`.
  - An ArgoCD sync wedged on `waiting for completion of hook
    batch/Job/homechef-api-temporal-namespace` — a Job that existed in no namespace.
    **Self-resolved after ~35 min.** Root cause unknown; will recur.
  - Nobody owns alerting for this. Worth an issue.
- **Minting a prod token** (this is how #904 was proven):
  `POST identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key=<EXPO_PUBLIC_GIP_API_KEY>`
  with `tenantId`, **plus a `Referer: https://fe3dr.com` header** — the key is
  referrer-restricted and curl fails without it. Then exchange at
  `POST <BFF>/auth/auto-login` `{id_token, expected_tenant_id}` → `session_token`,
  which is the Bearer the API wants. Raw GIP tokens get `bff_auth_failed`.
  Vendor host is **`vendors.fe3dr.com/api/v1`**, customer is `fe3dr.com/api`.
  ArgoCD's `argocd-initial-admin-secret` password is **stale** — login fails.
- **Emulator**: dev build, so it needs Metro **and** `adb reverse tcp:8081 tcp:8081`.
  "Unable to load script" happened twice — once Metro dead, once reverse lost on
  relaunch. Check `curl -s localhost:8081/status` first. Heavy API hammering can
  leave the app stuck on "Loading address…"; a cold restart clears it.
- `packages/mobile-shared` vitest is the **only** working mobile test bed; **4
  failures are pre-existing** (`auth-screens` ×3, `resolve-auth-error` ×1). 126
  passing at handoff.
- **Local `tsc` drifts from CI** via stale `.expo/types` — vendor showed 3 local
  errors while CI's own tsc job passed. Trust CI; re-measure locally, don't chase.
- **Never run `npx prettier`** — no config; rewrites whole files to double quotes.
