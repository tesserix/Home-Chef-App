## The one theme: correct money, wrong story

Every bug found is a **reporting** defect sitting on top of a correct transaction.

- **#933** — checkout hardcodes "Payments secured by **Razorpay**" while the gateway
  sheet says **Cashfree**, seconds apart in the same flow. The API already sends
  `paymentProvider` for exactly this (`delivery_quote.go:180-185`); the client
  discards it. **Third instance of the server-sends/client-discards shape** after
  #901 and #912 — worth a contract test rather than a third point fix.
- **#934** — "₹306 paid" when ₹303.48 moved; then **"₹394 paid" when ₹138.54 moved**.
  Reports `order.Total`, not the capture, and `%.0f` rounds it. Error scales with
  credit applied. In code merged the same day (`08efbe4f`).
- **#935** — money rounded on refund/payment screens. `lib/format.ts` already exists
  as "one source of truth" for this exact bug; **8 files use it, 6 roll their own
  rounding helper**, ~20 `toFixed(0)` money sites. Worst unfixed: group-order
  "Pay your share · ₹X" (a payment CTA) and meal-plan refund-choices (choosing
  money by a rounded number).
- **Funding spec** (`docs/superpowers/specs/2026-08-02-order-funding-transparency-design.md`,
  approved) — order detail shows Total ₹305.65 with no credit line while ₹303.48
  left the card. **Add notifications to its scope** — a push is what customers
  compare against a bank alert.

## Bugs that are not display

- **#938** — **Reorder silently multiplies the cart.** Three taps turned ₹240 into
  ₹1,480. Cross-chef is handled ("Replace cart?"); same-chef falls to a silent
  `else`. The realistic user error is tapping twice — they now order double.
- **#936** — checkout re-offers wallet credit already claimed by a pending order.
  **Not a double-spend** (ledger locks the row; the settle path names this case and
  refuses to pay the chef from uncollected credit) — but the second order lands in
  reconcile instead of completing, invisibly. Two live pending orders each claimed
  the same ₹255.75.
- **#932** — terminal states missing timestamps. Sharpened twice: the chef
  **reject** path stamps `refunded_at` but not `cancelled_at`, and the original
  query (`status='cancelled'`) **misses those rows entirely** because their status
  is `rejected`. Real count likely higher than 6. Hold-cancel and `CancelOrder` are
  both ruled out.
- **#928** — WebSocket flapping. **`tracking-ws` fails too, not just `notif-ws`**,
  same device/session/host, while `order-ws` stays up. Two independent hooks ⇒ the
  root cause is **server-side**; the client backoff fix is secondary. Also: the two
  sockets have different failure policies (one gives up into polling, one retries
  forever at ~1/sec) — reconcile them.
- **#931** — confirm-receipt reminders. **Downgraded to hardening**: zero orders are
  in `awaiting_customer_confirmation`, so it cannot fire today. Real gaps remain
  (guard omits `order.Status` while `MaybeAutoConfirm` right above it checks it;
  workflow has no cancellation signal unlike `PickupReadyWorkflow`).

## Environment and tooling

- **Prod DB reads:** `kubectl run pgq-$RANDOM -n homechef --rm -i --image=postgres:16-alpine
  --env=PGPASSWORD=… -- psql -h homechef-postgres-pooler-ro…` — read-only pooler,
  pod name must be **lowercase** (RFC 1123). Password: `kubectl get secret
  homechef-api-secrets -n homechef -o jsonpath='{.data.DB_PASSWORD}' | base64 -d`.
  Note it warns that credentials land in container logs — fine for one-off reads.
- **Metro:** start detached (`nohup … --clear & disown`) or a harness task reap
  kills it. **After a `git pull`, restart Metro** — the watcher misses bulk FS
  changes and serves a stale 1-module bundle. A real rebuild is ~4489 modules/17s.
- **The APK is a local debug build.** JS changes need only a reload; **`app.json`
  changes need `prebuild` + `gradlew assembleDebug`** (~6.5 min).
- **adb driving:** `uiautomator dump` costs 3-5s, so **timed UI (the now-10s
  pre-payment hold) cannot be caught by dump-then-tap** — either blind-tap known
  coordinates or have a human do it. **Scroll swipes over sliders drag them** —
  scroll at x≈1330, clear of the credit sliders, or you will silently change the
  amounts you are measuring.
- Sandbox card OTP is `111000`.
