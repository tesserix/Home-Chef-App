# Quick Task 260801-j3n: Hide the group / office order entry point (UI only)

Closes tesserix/Home-Chef-App#875.

## Goal

Stop leading customers into the group / office order flow — the split-pay half
isn't ready. Visibility gate only: no route removal, no code deletion, no
backend change. Flipping the flag back on is the ship switch.

## Context

`apps/mobile-customer/lib/features.ts` already exists precisely for this — it
holds client-side flags for surfaces deferred from v1, and
`GROUP_ORDERS_ENABLED` is one of them, currently `true`. The single visible
entry point (`ChefMenuTab.tsx:141`) is already wrapped in it. So the change is
the flag value; the rest of this plan is proving that's actually sufficient.

## Tasks

### Task 1 — Flip the flag

- **files:** `apps/mobile-customer/lib/features.ts`
- **action:** Set `GROUP_ORDERS_ENABLED` to `false`. Update the doc comment so
  it states why it's off (split-pay not live) rather than implying it shipped.
- **verify:** `grep -n "GROUP_ORDERS_ENABLED" apps/mobile-customer/lib/features.ts`
- **done:** Flag reads `false` with an accurate comment.

### Task 2 — Prove no other entry point is reachable

- **files:** none (audit)
- **action:** Sweep the customer app for group-order navigation that is not
  behind the flag:
  `grep -rn "group-order\|/group/\|useGroupOrder" apps/mobile-customer/app apps/mobile-customer/components`
  Classify each hit as (a) gated, (b) invite/deep-link path that must stay
  reachable, or (c) an ungated entry point that needs gating.
- **verify:** Every hit falls in (a) or (b); anything in (c) gets wrapped in
  `GROUP_ORDERS_ENABLED` in this same commit.
- **done:** No ungated way for a customer to *start* a group order.

### Task 3 — Typecheck

- **files:** none
- **action:** Run the customer app's typecheck. `features.ts` types the flags as
  `boolean` (not literal `true`), so narrowing must not break call sites.
- **verify:** typecheck exits clean
- **done:** No new type errors.

## must_haves

**truths:**
- A customer cannot initiate a group order from anywhere in the app.
- An existing invite deep-link (`homechef-customer://group/<token>`) still
  resolves to the group hub — this is a visibility gate, not a teardown.
- The order-detail confirmation sheet and every other unrelated surface are
  untouched.

**artifacts:**
- `apps/mobile-customer/lib/features.ts` with `GROUP_ORDERS_ENABLED = false`

**key_links:**
- `apps/mobile-customer/lib/features.ts:18`
- `apps/mobile-customer/components/chef/ChefMenuTab.tsx:141`
- `apps/mobile-customer/app/group/[code].tsx` (must remain reachable)
- `apps/mobile-customer/app/group-order/[id].tsx` (must remain reachable)

## Out of scope

Deleting the group-order routes, hooks, or API calls. Removing the header
close/done affordances on other sheets (that's #877).
