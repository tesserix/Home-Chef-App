<objective>
GH #869 (re-scoped, two fixes):

1. `useUnreadCount` / `useNotificationList` in `packages/mobile-shared/src/hooks/useNotifications.ts` have no auth guard, so they fire on mount regardless of sign-in state. `useUnreadCount` is mounted on the customer AND vendor Home tabs, both of which are reachable while signed out (customer explicitly supports guest browsing). Each unauthenticated mount 401-storms: React Query's global `retry: 2` (set in both apps' `_layout.tsx`) fires 3 attempts, and the axios response interceptor separately does one silent-refresh-and-retry per attempt — matching the issue's observed 11×401 vs 3×200 on `/api/v1/notifications/unread-count`.

2. The notification WebSocket (and its siblings) fail completely silently: `onerror` only increments a counter, `onclose` reconnects up to `MAX_WS_FAILURES` and then just stops — no log, no signal, nothing. This is the same silent-failure class as #870.

Purpose: stop the unauthenticated 401 storm at the source (gate + don't retry auth failures), and make WS failures greppable so the next "is the socket even trying?" question doesn't require patching in temporary logs again.

Output:
- `useUnreadCount`/`useNotificationList` take an `enabled` option; every caller in customer + vendor passes `isAuthenticated` from the shared auth store.
- Both queries stop retrying on 401 specifically (still retry transient network/5xx errors, same cap as today).
- `useNotificationSocket` and its three sibling WS hooks (`useOrderStatusWS`, `useOrderTrackingWS`, `useLiveUpdates`) log connect / error / close-and-reconnect / terminal-give-up with a consistent bracket-prefixed, token-free line.
</objective>
