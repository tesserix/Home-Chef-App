# Quick Task 260801-y88: Distinguish upstream gateway failure from "not paid" in verify (#872 final item) — Summary

Distinguishes a genuine Cashfree/Razorpay upstream failure (transport error, timeout, 5xx, unparseable response) during payment verify from a gateway that cleanly reports "no captured payment" — the former now answers 502 (retryable), the latter still answers 400 (terminal), and "gateway not configured" now answers 503 for Cashfree, matching the pre-existing sibling checks.

## What changed

- `services.SettleCashfreeOrder` signature changed from `(bool, string)` to `(bool, string, error)`. Two new sentinel errors added: `ErrPaymentGatewayUnavailable` (gateway client not configured) and `ErrPaymentGatewayFetchFailed` (the mandatory `cf.SuccessfulPayment` fetch itself failed, wrapped with `%w`). Every terminal branch (`payment == nil`, a `ValidateCapturedPayment` rejection, the success path) still returns a `nil` error — meaning unchanged.
- `services.order_payment_reconcile_cron.go`'s one call site updated to discard the new third return value (`ok, reason, _ = SettleCashfreeOrder(order)`) — it only ever logs `reason`, no behavior change.
- New handler-local helper `handlers.cashfreeSettleStatus(err error) int` maps `ErrPaymentGatewayUnavailable` → 503, `ErrPaymentGatewayFetchFailed` → 502, anything else (including `nil`) → 400. Both `verifyCashfreePayment` and `finishCashfreeFromGateway` (the create-leg already-PAID recovery) now call it instead of hardcoding 400.
- `handlers.verifyRazorpayPayment`'s `rz.FetchPayment` failure branch changed from `500 "Failed to verify payment"` to `502 "Could not verify payment with the gateway — please try again in a moment"` — the one status code this task changes on the Razorpay leg, matching Cashfree's same "mandatory server fetch failing is retryable" contract. The `rz == nil` (503, unchanged) and `SettleRazorpayOrderFromPayment` rejection (400, unchanged) branches were left untouched.
- Six new/confirmed test scenarios added across `payment_cashfree_test.go` and `payment_test.go` (see below).
