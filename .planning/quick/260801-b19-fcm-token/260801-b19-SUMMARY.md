# Quick Task 260801-b19: Register FCM device tokens so push actually delivers — Summary

Closes tesserix/Home-Chef-App#870. Executed exactly as planned, no deviations.

## What changed

**`packages/mobile-shared/src/hooks/usePushToken.ts`**
- Simulator guard narrowed from `!Device.isDevice` to `Platform.OS === 'ios' && !Device.isDevice`
  (added `Platform` import from `react-native`). Android emulators with Play Services can now
  register a token for the first time; only iOS simulators remain blocked.
- Every silent exit in `getRawFCMToken` now logs a distinct, greppable `[push]` `console.warn`:
  iOS-simulator skip, and permission-not-granted (includes the actual `finalStatus`, e.g.
  `denied` vs `undetermined`).
- Added and exported `registerDeviceTokenSafe(client, token): Promise<boolean>` — wraps the
  existing `registerDeviceToken`, never throws, logs a truncated token on success
  (`console.log`) or the error on failure (`console.warn`).
- `registerDeviceToken`, `deviceTokenPath`, and the `ExponentPushToken` guard are untouched.

**`apps/mobile-customer/app/_layout.tsx`, `apps/mobile-vendor/app/_layout.tsx`**
- Swapped the `registerDeviceToken` import/calls (initial + rotation-listener) for
  `registerDeviceTokenSafe`, so a failed/thrown initial registration no longer prevents the
  rotation, badge, or deep-link-tap listeners from attaching.
- Added `tokenRegisteredRef = useRef(false)`, set from the safe helper's return value, reset to
  `false` in the push effect's cleanup (so a logout/login cycle re-attempts for the new session).
- Extended the existing `AppState.addEventListener('change', ...)` callback (the one already
  driving `focusManager`) to re-attempt registration on foreground when not yet registered and
  the user is authenticated — no second `AppState` listener added.

**`apps/mobile-delivery/app/_layout.tsx`**
- Same import swap, `tokenRegisteredRef`, safe initial/rotation calls, and cleanup reset as
  customer/vendor.
- This app had no existing `AppState`/`focusManager` effect, so added one new, dedicated
  `AppState.addEventListener` effect containing only the reattempt body (no React Query focus
  wiring — explicitly out of scope, commented as such).

**`packages/mobile-shared/src/__tests__/push-observability.test.ts`** (new)
- Covers: iOS simulator skip (no `getPermissionsAsync` call, warns `'iOS simulator'`); Android
  emulator does NOT short-circuit and resolves a real token; permission-denied resolves `null`
  and warns `'denied'`; `registerDeviceTokenSafe` returns `true`+logs on success, returns
  `false`+warns+never throws on rejection.
- `react-native` mocked per-file via `vi.hoisted` + `vi.mock` (mutable `Platform.OS`), since the
  package's global vitest alias for `react-native` hardcodes `Platform.OS: 'ios'` and isn't
  mutable per test.

## Deviations from plan

`registerDeviceTokenSafe` helper, wrap-don't-reorder listener setup, and reattempt-via-existing-
listener (customer/vendor) vs. new-dedicated-listener (delivery).

One minor note on a verify-step check: the plan's Task 1 verify step expected
`grep -c "registerDeviceTokenSafe" usePushToken.ts` to be at least 2 ("definition + export").
The actual code uses a single-line `export async function registerDeviceTokenSafe(...)`
(matching this codebase's existing style for `registerDeviceToken` two functions above it), so
`grep -c` (counting matching lines) returns 1, not 2. The function is correctly defined and
exported — confirmed by the test file successfully importing and exercising it. This is a
mismatch in the plan's verify-step assumption about code style, not a functional gap.
