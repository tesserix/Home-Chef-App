<objective>
Fix GitHub #696 (re-scoped): the customer subscriptions screen offers "Skip" on today's tiffin meal, which `POST /meal-subscriptions/:id/skip` rejects 100% of the time because the server only accepts a date strictly after today in IST (`apps/api/handlers/meal_subscription.go` Skip handler). The screen's own eligibility filter uses device-local midnight (`startOfToday()` + `new Date().setHours(0,0,0,0)`), which both includes today (wrong inequality) and computes "today" in the wrong timezone (device-local, not IST) — a second, independent way to offer an unskippable day to a customer running behind IST. Two user-facing strings also name a "cutoff" that this handler never checks.

Purpose: Stop offering a control that always fails for today, correct it for every device timezone (not just IST-adjacent ones), tell the customer the real rule before they tap, and stop both messages from lying about a cutoff that isn't enforced here.

Output: A pure, unit-tested `isSkippableMealDay` helper in `packages/mobile-shared` (the only working vitest bed in this monorepo); `subscriptions.tsx` wired to it with an explanatory line and corrected error copy; one corrected string in the Go Skip handler.
</objective>

```typescript
const IST_OFFSET_MS = 5.5 * 60 * 60 * 1000;
function istDay(now: Date, offsetDays: number): { iso: string; midnightMs: number } {
  const wall = new Date(now.getTime() + IST_OFFSET_MS);
  wall.setUTCDate(wall.getUTCDate() + offsetDays);
  const y = wall.getUTCFullYear();
  const m = String(wall.getUTCMonth() + 1).padStart(2, '0');
  const d = String(wall.getUTCDate()).padStart(2, '0');
  return { iso: `${y}-${m}-${d}`, midnightMs: Date.parse(`${iso}T00:00:00+05:30`) };
}
```
