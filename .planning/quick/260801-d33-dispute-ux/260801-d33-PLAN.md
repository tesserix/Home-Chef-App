## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Customer mobile app → Go API (`apps/api`) | `POST /v1/orders/:id/cancel-request/dispute` sends `{ reason }` as free text with the customer's Bearer token; server is trusted, the reason string is user-authored and untrusted |
| `dispute_reason` → admin arbitration UI | Stored server-side, eventually rendered by the admin UI in a different repo (`tesserix-home`, part 2 of #876) — out of scope for this plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-d33-01 | Tampering | Combined `reason` string sent to `/cancel-request/dispute` | accept | Server stores it as free text (`body.Reason`, no length cap/validation server-side); client caps free-text elaboration at 500 chars via `TextInput maxLength`, but this is a UX bound, not a security control — no backend change is in scope here |
| T-d33-02 | Information Disclosure | `friendlyErrorMessage` surfacing the server's 409/404 body to the customer | mitigate | `friendlyErrorMessage` already strips transport noise (status codes, axios phrasing) and only surfaces the API envelope's `message`/`error` field, which the handler already writes as customer-safe copy ("This cancellation can't be disputed") — no raw status/stack ever reaches the UI |
| T-d33-03 | Denial of Service (self-inflicted, client→API) | Double-tap firing duplicate dispute POSTs | mitigate | Trigger control `disabled={dispute.isPending}` (Task 2); server additionally 409s a repeat regardless, so this is defense-in-depth, not the only guard |
| T-d33-04 | Repudiation / Elevation of Privilege | n/a — this plan adds no new auth surface, endpoint, or role | accept | Existing `DisputeCancellation` handler already scopes the query to `customer_id` from the authenticated session; unchanged |
| T-d33-05 | Information Disclosure | Rendering of the free-text `dispute_reason` in the admin UI (part 2, `tesserix-home`) | accept — out of scope | That repo's own render surface is responsible for escaping; not verifiable or fixable from this repo/plan |
