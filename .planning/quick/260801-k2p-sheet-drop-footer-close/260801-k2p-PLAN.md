# Quick Task 260801-k2p: Drop the footer Close button from sheets, add drag-to-dismiss

Closes tesserix/Home-Chef-App#877.

## Goal

Remove the full-width "Close" bar from the bottom of the customer app's sheets,
and make the sheets dismissable the way they already *look* dismissable.

Owner decision (2026-08-01): **add real drag-to-dismiss** rather than shipping
the button removal alone. Removing Close without it would leave iOS with
backdrop-tap as the only exit, while `SheetBase` renders a grabber pill that
advertises a drag it doesn't support.

## Blast radius (verified, not assumed)

`SheetBase` is rendered in exactly four places — the `-l` grep is misleading
because `Dialog.tsx`, `Toast.tsx` and `UndoSnackbar.tsx` only *mention* it in
comments:

- `apps/mobile-customer/components/home/FilterSheet.tsx:136`
- `apps/mobile-customer/components/address/AddressSwitcherSheet.tsx:65`
- `packages/mobile-shared/src/ui/Sheet.tsx:74`
- `packages/mobile-shared/src/ui/ReportSheet.tsx:109,119`

`<Sheet>` has exactly two call sites, and **both already pass `cancelLabel`**
(`order/[id]/index.tsx:1031` → "Not yet", `MealPlanSheet.tsx:36` → "Close"). So
making the cancel button opt-in breaks no existing caller — there is no
consumer relying on the default "Cancel".

`MenuCategorySheet` — the sheet in the issue screenshot — does **not** use
`SheetBase`. It is a bespoke `Modal` with its own backdrop and no grabber, so
it needs the drag wired separately.

## Tasks

### Task 1 — Extract a shared drag-to-dismiss hook

- **files:** `packages/mobile-shared/src/ui/useSheetDrag.ts` (new),
  `packages/mobile-shared/src/ui/index.ts`
- **action:** New `useSheetDrag({ translateY, onDismiss, reduceMotion })`
  returning `panHandlers`. Downward-only tracking; release past a distance
  **or** velocity threshold dismisses, otherwise springs back to 0.
- **Critical constraint:** `translateY` is already driven by
  `useNativeDriver: true` timings in `SheetBase`. Running a JS-driven
  `Animated.event` on that same node throws *"Attempting to run JS driven
  animation on animated node that has been moved to 'native'"*. So the drag
  must use `translateY.setValue(dy)` (which is legal on a native-driven node)
  and the spring-back must itself be a `useNativeDriver: true` timing. Do not
  reach for `Animated.event`.
- **verify:** typecheck; hook is exported from the barrel
- **done:** One implementation, consumed by both sheet shells.

### Task 2 — Wire drag into SheetBase, make the grabber real

- **files:** `packages/mobile-shared/src/ui/SheetBase.tsx`
- **action:** Wrap the grabber in a drag region carrying `panHandlers`, with
  padding so the touch target is reasonable (the pill itself is 40×4). Honor
  `reduceMotion` for the spring-back. Leave the backdrop `Pressable` alone —
  it stays the accessible dismissal path, since a pan gesture is invisible to
  VoiceOver.
- **verify:** typecheck; FilterSheet / AddressSwitcherSheet / ReportSheet still
  render and open
- **done:** Dragging the grabber down dismisses; a short drag springs back.

### Task 3 — Make the `Sheet` cancel button opt-in

- **files:** `packages/mobile-shared/src/ui/Sheet.tsx`
- **action:** Only render the ghost cancel `Button` when the caller passes
  `cancelLabel`. Drop the `= 'Cancel'` default. Document that omitting it means
  "dismiss via backdrop or drag".
- **verify:** `order/[id]/index.tsx` still renders "Not yet"
- **done:** Confirmation sheets keep their real choice; pure-dismiss sheets
  don't render a redundant button.

### Task 4 — Drop the Close affordances at the three call sites

- **files:** `apps/mobile-customer/components/meal-plan/MealPlanSheet.tsx`,
  `apps/mobile-customer/components/chef/MenuCategorySheet.tsx`
- **action:**
  - `MealPlanSheet`: remove `cancelLabel="Close"`.
  - `MenuCategorySheet`: remove the footer `Pressable` (lines 104-119) and its
    wrapper `View`; add a grabber + drag region using the Task 1 hook; rebalance
    bottom padding so the last category isn't flush to the screen edge.
- **verify:** typecheck; no "Close" string left in either file
- **done:** No footer Close bar anywhere.
