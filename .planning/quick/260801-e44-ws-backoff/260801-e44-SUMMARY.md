# Sockets must not give up permanently (#892) — Summary

## What changed

1. **`packages/mobile-shared/src/utils/socket-backoff.ts`** — new `socketReconnectDelayMs(consecutiveFailures)`, a thin wrapper around the existing `backoffMs` curve from `support/outbox.ts` (1s → 2s → 4s → 8s → 16s → capped 30s). No new curve invented. Exported via `./utils` subpath. 4 new vitest tests (sane attempt-1 value, monotonic growth, 30s ceiling never exceeded, never 0/negative).

2. **`apps/mobile-customer/hooks/useOrderStatusWS.ts`** (no fallback — worst case) — removed the permanent give-up; `onclose` now always reschedules via `socketReconnectDelayMs`. Fixed the false "no further reconnects" log line to log the scheduled delay instead.

3. **`apps/mobile-customer/hooks/useOrderTrackingWS.ts`** — polling fallback trigger (3 failures) unchanged, but the socket now keeps retrying with backoff even while polling is active. On successful reopen, drops the polling fallback and logs recovery. `connect()` no longer bails on `useFallback`.

4. **`apps/mobile-vendor/hooks/useLiveUpdates.ts`** — SSE fallback trigger (4 failures) unchanged, but WS now keeps retrying in the background instead of the old code path that opened SSE and never attempted WS again. On successful WS reopen, closes the SSE stream and logs recovery. Guarded to avoid opening a second SSE stream while one is already active.

All three: added a narrowly-scoped `AppState` "change" listener (pattern copied from `useSupportChat.ts`'s existing foreground-reconnect wiring) that, on returning to foreground, clears any pending backoff timer, resets the failure counter, and reconnects immediately if the socket isn't already open — so backgrounding doesn't strand the user behind a stale long backoff. Timers are cleared on unmount and when `enabled` goes false (verified for both the mount effect and the new foreground effect).

## Backoff curve used

Reused `backoffMs` unchanged: `Math.min(30_000, 1_000 * 2 ** (attempts - 1))` → 1s, 2s, 4s, 8s, 16s, then capped at 30s indefinitely. Never 0, never unbounded.
