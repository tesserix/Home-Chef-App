# Phase 260802-123 Plan 01: Plans tab shows recurring tiffin subscriptions Summary

Added a pure, unit-tested `pickSubscriptionMealDay` day-selector in `packages/mobile-shared` and wired a new `SubscriptionsSummary` section above `MealPlanList` on the customer Plans tab, so a customer with only an active recurring tiffin no longer sees the meal-plan-only empty state.

## What Was Built

**Task 1 — `pickSubscriptionMealDay` selector (TDD, RED→GREEN):**
- `packages/mobile-shared/src/utils/subscription-meal-day.ts` exports `SubscriptionMealDayLike`, `PickedSubscriptionMealDay<T>`, and `pickSubscriptionMealDay(days, now)`.
- Filters to `status === 'scheduled'` entries whose IST calendar day is not strictly past (`!isPastMealDay`, reused unmodified from `./ist-calendar-date`, the #696 helper), sorts ascending by RFC3339 date string with a `lunch`-before-`dinner` tie-break for same-`date` entries, and returns the first match with an `isToday` flag computed via `istCalendarDate` equality.
- Re-exported from `packages/mobile-shared/src/utils/index.ts`.
- 6 new vitest cases in `subscription-meal-day.test.ts` (today-scheduled, later-this-week, nothing-upcoming, only-past days masking a stale `'scheduled'` row, same-day lunch/dinner tie-break using identical `date` values matching the real API shape, today-skipped-falls-through). All fixed-instant, no mocks, matching the `ist-calendar-date.test.ts` style.
- Committed RED (`test(260802-123): add failing tests...`, `6e8af3f0`) then GREEN (`feat(260802-123): implement pickSubscriptionMealDay...`, `e077aef5`).

**Task 2 — `SubscriptionsSummary` component + wiring:**
- `apps/mobile-customer/components/meal-plan/SubscriptionsSummary.tsx`: calls `useMealSubscriptions()`; renders a skeleton row while loading, a bordered retry row on error, `null` when there are zero `active`/`trialing` subscriptions (so `MealPlanList`'s existing empty state is untouched for meal-plan-only or neither-case customers), otherwise one `SubscriptionRow` per active/trialing subscription.
- Each `SubscriptionRow` independently calls `useMealFulfillments(sub.id)` and computes its own line via `pickSubscriptionMealDay` — one subscription's fetch failing does not blank a sibling row.
- Copy exactly matches the locked decision: `"Tiffin · today: Lunch"` / `"Tiffin · next: Tue lunch"`, with `shortWeekday()` converting through `istCalendarDate` + explicit `timeZone: 'UTC'` in `toLocaleDateString` so the displayed weekday never depends on device-local timezone (the same class of bug #696 fixed).
- Tapping any row calls `router.push('/subscriptions')` — no new Skip/Pause/Cancel logic was added.
- `apps/mobile-customer/app/(tabs)/plans.tsx` now renders `<SubscriptionsSummary />` immediately above `<MealPlanList />`; no other line in that file was touched.
- Single commit (`feat(260802-123): add SubscriptionsSummary to Plans tab for GH-900`, `c9f380bb`) — the plan's own `<behavior>` block states there is no jest-expo bed for app-level component tests in this repo, so per-state behavior was pinned in prose there instead of in an automated RED/GREEN cycle (see TDD Gate Compliance below).

`ActivePlanChip` was not imported, referenced, or modified anywhere (confirmed by grep — see Self-Check).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a tie-break test that would have passed for the wrong reason**
- **Found during:** Task 1, writing the same-day lunch/dinner tie-break test.
- **Issue:** The plan's own worked example used different time-of-day values for the lunch/dinner fixture rows (`06:30Z` vs `12:30Z`), which meant the plain lexicographic date-string sort — not the slot tie-break — would have produced the correct-looking result, silently under-testing the tie-break logic the test claims to cover.
- **Fix:** Set both fixture rows to the identical `date` value (IST midnight of the calendar day), matching the real API shape confirmed by the #696 SUMMARY note that `MealSubscriptionFulfillment.Date` stores IST midnight regardless of slot — so the test now genuinely exercises the `SLOT_ORDER` tie-break.
- **Files modified:** `packages/mobile-shared/src/__tests__/subscription-meal-day.test.ts`
- **Commit:** `6e8af3f0`

**2. [Rule 1 - Bug] Fixed the skeleton row's flex direction**
- **Found during:** Task 2, code review before commit.
- **Issue:** `SkeletonRow` initially reused `styles.card` (which sets `flexDirection: 'row'`) directly for two stacked skeleton lines, which would have rendered them side-by-side instead of stacked as the plan specifies.
- **Fix:** Added a `skeletonCard` style override (`flexDirection: 'column', alignItems: 'stretch'`) composed onto `styles.card` for the skeleton state only; the real row (with icon + text + chevron) keeps the row layout.
- **Files modified:** `apps/mobile-customer/components/meal-plan/SubscriptionsSummary.tsx`
- **Commit:** `c9f380bb`

None else — plan executed as written otherwise.
