<objective>
Fix GitHub #900: the customer app's Plans tab (`app/(tabs)/plans.tsx`) renders only `<MealPlanList />`, which reads `meal_plans` exclusively. A customer whose only commitment is a recurring `meal_subscriptions` tiffin opens the tab named "Plans" and is told, via `MealPlanList`'s empty state, that they have no plans at all — even though they are actively subscribed and being charged.

Per the locked owner decision: for each active recurring subscription, show today's scheduled meal if one exists, otherwise the next upcoming scheduled day (e.g. "Tiffin · today: Lunch" / "Tiffin · next: Tue lunch"). Tapping opens the existing `/subscriptions` screen, where Skip/Pause/Cancel already live — this plan adds no new inline actions, no new sheet, and no static "N days/week" summary (all three were explicitly rejected).

Purpose: A subscribed customer must be able to see, from the tab literally named "Plans", that they have an active tiffin and what it's doing today — without duplicating logic `/subscriptions` already owns.

Output: A pure, unit-tested day-selector in `packages/mobile-shared` (the only working vitest bed in this monorepo), and a new `SubscriptionsSummary` section wired above the existing `MealPlanList` on the Plans tab.
</objective>
