# Quick Task 260801-r51: Order-level payment reconcile cron (#872 step 2) — Summary

One-liner: extracted the order-payment completion/settlement core out of
`handlers` into `services/order_payment_settle.go` (single implementation
shared by both HTTP verify legs), then added
`services/order_payment_reconcile_cron.go` — a 5-minute-grace, 5-minute-interval
cron that settles captured-but-unconfirmed orders through that same core,
closing the gap step 1's stale-order gateway gate left open.

## What shipped

**Task 1** — Moved the guarded completion transaction
(`CompletionBlockedStatuses`, `NotifyChefNewOrderTx`, `CompleteOrderPaymentTx`,
`CompleteRazorpayOrderTx`, `CompleteCashfreeOrderTx`) from `handlers/payment.go`
/ `handlers/payment_cashfree.go` into new `services/order_payment_settle.go`,
exported. Deleted `handlers/payment_complete_generic_test.go` and
`handlers/payment_complete_race_test.go`; recreated all 6 tests in
`services/order_payment_settle_test.go` with unchanged assertions.

**Task 2** — Moved the wallet-settlement cluster (`OrderSettlements`,
`ApplyChefRecoveryDeduction`, `DebitOrderWallet`, `SettleWalletTopUps`,
unexported `settleWalletTopUpsWith`, `SettleOrderWallet`) into the same file.
Deleted the `chefNetPayout` handlers-local wrapper (7 call sites now call
`services.ChefNetPayoutFor` directly). Deleted
`handlers/wallet_topup_settle_test.go`; recreated its 3 tests in new
`services/wallet_topup_settle_test.go`. Deleted the 5 `TestOrderSettlements_*`
tests + `seedChefPenalty` helper from `handlers/payment_test.go`; recreated them
in `services/order_payment_settle_test.go`, reusing the sibling
`payout_recovery_test.go`'s `newRecoveryTestDB`/`seedPenalty` rather than
duplicating.

**Task 3** — Extracted the two gateway-settle cores:
`SettleCashfreeOrder(order)` (moved `settleCashfreeOrder` verbatim, dropping the
redundant `cfOrderID` param — uses `order.RazorpayOrderID` throughout) and new
`SettleRazorpayOrderFromPayment(order, payment)` (built from the
post-signature-check portion of `verifyRazorpayPayment`). Rewired
`handlers/payment_cashfree.go`'s `finishCashfreeFromGateway` /
`verifyCashfreePayment` and `handlers/payment.go`'s `verifyRazorpayPayment` to
call into `services`. The Checkout signature check now runs immediately after
the Razorpay fetch (a deliberate, harmless reordering — the client-verifiable
check no longer waits on the gateway-authoritative one that moved into the
shared core). Full `go test ./...` is the regression net for this task — zero
edits needed in `payment_cashfree_test.go` / `payment_verify_loyalty_test.go`.

**Task 4** — New `services/order_payment_reconcile_cron.go`:
`reconcileOrderPayments(db, now)` (the testable core), `runOrderPaymentReconcileScan`,
`StartOrderPaymentReconcileCron`, registered in `cronJobs()` right after
`"stale-order"`. 5-minute grace, 5-minute interval, batch 100. Query:
`payment_status='pending' AND razorpay_order_id <> '' AND status NOT IN
(cancelled, rejected, refunded, delivered) AND created_at < now-grace`,
`Preload("Chef").Preload("Delivery.DeliveryPartner")`. Per order, switches on
`NormalizeProvider`: Cashfree → `SettleCashfreeOrder`; Razorpay → local
`settleRazorpayFromDiscovery` (resolves the gateway, calls
`FetchOrderPayments`, scans for the first captured entry bound to the order,
hands it to `SettleRazorpayOrderFromPayment`); default (Stripe/unrecognised) →
skipped silently, out of scope by construction. 9 test scenarios in
`services/order_payment_reconcile_cron_test.go`, all passing.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `countOutbox`/`paymentStatusOf` helpers still needed by surviving handler tests**
- **Found during:** Task 1
- **Issue:** The plan's file inventory said `handlers/payment_complete_race_test.go`'s helpers `countOutbox`, `paymentStatusOf`, `loadPayOrder` move wholesale to `services`. It missed that `countOutbox`/`paymentStatusOf` are also called by `payment_cashfree_test.go`, `payment_webhook_guard_test.go`, and `meal_plan_skip_test.go` — all staying in `handlers`, unmoved. Deleting the file wholesale broke the `handlers` package's test build.
- **Fix:** Re-added `countOutbox`/`paymentStatusOf` (identical bodies) to `handlers/payment_test.go`, the package's existing shared-helper file. `loadPayOrder` had no other caller, so it did not need to survive in `handlers`.
- **Files modified:** `apps/api/handlers/payment_test.go`
- **Commit:** 4fbac595

**2. [Rule 3 - Blocking] `services.countOutbox` name collision with an existing services-package helper**
- **Found during:** Task 1
- **Issue:** `services/payout_hold_test.go` already defines `func countOutbox(t, db, subject) int` (returns `int`, not `int64`). Using the plan's literal helper name in the new `services/order_payment_settle_test.go` would not compile (duplicate symbol, different signature).
- **Fix:** Named the relocated helpers `countOutboxTx`/`paymentStatusOfTx` instead.
- **Files modified:** `apps/api/services/order_payment_settle_test.go`
- **Commit:** 4fbac595

**3. [Rule 1 - Bug] `LogSystemAudit` panic in relocated `TestOrderSettlements_*` tests**
- **Found during:** Task 2
- **Issue:** `ApplyChefRecoveryDeduction` → `LogSystemAudit` reads the package-global `database.DB`, not the `db` parameter `OrderSettlements`/`ApplyChefRecoveryDeduction` take explicitly. The relocated test setup passed `db` to the functions under test but never swapped `database.DB`, so `LogSystemAudit`'s `database.DB.Create(&entry)` ran against a nil `*gorm.DB` and panicked (nil pointer dereference) on the recovery-deduction-with-audit-row test.
- **Fix:** `setupOrderSettlementsDB` now swaps `database.DB = db` with a `t.Cleanup` restore, matching how `setupTopUpDedupDB`-based tests already had to for `settleWalletTopUpsWith`.
- **Files modified:** `apps/api/services/order_payment_settle_test.go`
- **Commit:** 1c06591d

**4. [Rule 1 - Bug] Missing `payment_method` column in the reconcile cron's test schema**
- **Found during:** Task 4
- **Issue:** `setupStaleOrderDB`'s base `orders` table (from `setupCancelRefundDB`) has no `payment_method` column. `CompleteCashfreeOrderTx`/`CompleteRazorpayOrderTx` stamp it alongside `payment_status=completed`, so every settle-success scenario failed the underlying `UPDATE` with "no such column: payment_method" and silently left the order `pending`.
- **Fix:** `setupReconcileDB` adds `ALTER TABLE orders ADD COLUMN payment_method TEXT DEFAULT ''` before creating the chef/delivery tables.
- **Files modified:** `apps/api/services/order_payment_reconcile_cron_test.go`
- **Commit:** caf06cc3

### Scope Boundary — Deferred, Not Fixed

**Pre-existing landmine: `GetRazorpayFor(ChefModeLive)` panics when `config.AppConfig` is nil and Secret Manager is unreachable.** `services/razorpay.go`'s `fetchRazorpayFromSM` has a live-mode-only dev-fallback branch (`if !models.IsTestMode(mode) { cfg := config.AppConfig; if !isPlaceholderValue(cfg.RazorpayKeyID) ... }`) that dereferences `config.AppConfig` without a nil check. In this package's test binary `config.AppConfig` is nil unless another test happened to set it (with cleanup), so any test that calls `GetRazorpayFor(models.ChefModeLive)` with an empty client cache and no Secret Manager crashes with a nil-pointer panic. Discovered while drafting a "top-level bail when nothing is configured" test for the new cron and a `runOrderPaymentReconcileScan` panic-smoke-test — both removed rather than worked around, since `services/razorpay.go` is outside this task's `files_modified` list. Every Razorpay-touching scenario in `order_payment_reconcile_cron_test.go` seeds the live slot via `withRazorpayServerFor` specifically to stay clear of this branch, mirroring how `stale_order_cron_test.go`'s existing coverage already does. Logged here for a future fix (guard `cfg == nil` before dereferencing), not fixed in this PR.

None of the above are money-path defects — all four are test-infrastructure gaps discovered while relocating coverage, fixed inline per Rule 1/3, or explicitly out-of-scope per Rule-priority (architectural-adjacent file outside `files_modified`).
